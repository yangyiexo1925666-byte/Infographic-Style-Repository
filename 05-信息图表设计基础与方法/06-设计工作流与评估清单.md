# 信息图表设计工作流与评估清单

## 1. 完整设计工作流

| 阶段 | 工作任务 | 主要产出 | 检查重点 |
|---|---|---|---|
| A. 目标与受众 | 明确传播目标、读者、场景与核心问题 | 项目简报、读者任务 | 目标是否明确？ |
| B. 数据收集与清洗 | 收集数据、核验来源、统一口径、处理缺失与异常 | 数据源清单、清洗记录 | 数据是否可信且可追溯？ |
| C. 数据类型识别 | 判断名义、顺序、离散、连续变量 | 数据字段表 | 类型与测量方式是否一致？ |
| D. 信息结构分析 | 识别时间、层级、分类、字母表、地理及复合关系 | 信息架构图 | 主导逻辑是否清晰？ |
| E. 信息提炼与叙事 | 定义问题、发现模式、筛选重点、安排顺序 | 核心观点、叙事大纲 | 是否从数据中形成有证据的观点？ |
| F. 图表与视觉编码 | 选择图表、视觉变量、符号、色彩和版式 | 图表草图、视觉编码表 | 编码是否准确且可读？ |
| G. 视觉设计与实现 | 建立网格、字体、层级、标注、交互或输出格式 | 设计稿、原型或成品 | 形式是否服务内容？ |
| H. 验证与迭代 | 检查数据、图形诚实、可访问性和读者理解 | 测试记录、修订清单 | 读者是否能正确理解？ |

## 2. 从数据到洞见的四步

1. **数据分析：** 识别模式、趋势、异常和变量关系。
2. **问题定义：** 明确图表要回答的核心问题。
3. **信息筛选：** 保留与任务相关的重点，记录筛选范围和限制。
4. **逻辑构建：** 将内容组织为可理解的顺序、层级或比较关系。

信息层是数据与受众之间的桥梁。仅仅把数据画出来，并不等于形成了有效的信息表达。

## 3. 叙事与阅读结构

- 先呈现主题、问题或关键结论。
- 通过主图呈现核心证据。
- 使用辅助图表、注释和图例补充背景与细节。
- 按照读者的任务安排信息顺序，而不是仅按设计者收集资料的顺序排列。
- 复杂内容可以采用概览—细节结构，让读者按需深入。

## 4. 读者测试方法

### 4.1 快速理解测试

让目标读者短时间浏览作品，询问：
- 这张图表主要讲什么？
- 最重要的发现是什么？
- 哪些变量或对象正在被比较？
- 图表中的颜色、符号和尺度分别代表什么？

### 4.2 任务测试

给读者一个具体任务，例如找出变化最大类别、比较两个地区或定位某个时间点。观察是否需要反复搜索、记忆数值或自行排序。

### 4.3 记忆与理解测试

可在阅读后立即询问主要结论，并在一段时间后再次检查记忆。测试间隔应根据项目目标制定，不应把某个固定时长视为通用标准。

### 4.4 观察阅读路径

在条件允许时，可以观察读者视线或点击路径，判断标题、主图、注释和交互入口是否符合预期。眼动数据只是辅助证据，仍需结合任务完成情况和访谈解释。

## 5. 读者认知负担的四个常见来源

- 反复搜寻问题中提到的数据；
- 在脑海中记住多个数值；
- 自行排列数值大小；
- 在不同对象之间进行比较。

设计者应通过排序、分组、直接标注、共同尺度和合理布局，主动承担可以由设计完成的认知工作。

## 6. 作品发布前检查清单

### 内容与数据
- [ ] 主题与核心问题明确。
- [ ] 数据来源、单位、时间范围和统计口径清楚。
- [ ] 数据类型与变量定义准确。
- [ ] 缺失值、筛选条件和数据处理方式有记录。
- [ ] 结论没有超出数据证据能够支持的范围。

### 图表与编码
- [ ] 图表类型与读者任务和数据结构匹配。
- [ ] 轴、基线、尺度、单位与排序正确。
- [ ] 颜色、形状、大小和符号的含义明确。
- [ ] 面积、气泡、3D 和透视没有夸大或扭曲数据。
- [ ] 图例、标注和来源说明完整。

### 视觉与体验
- [ ] 标题、主图、辅助信息与注释层级清晰。
- [ ] 字体、对齐、留白和风格一致。
- [ ] 不存在无助于理解的图表垃圾。
- [ ] 颜色对比与可访问性得到检查。
- [ ] 交互（如有）有明确任务、反馈和重置方式。

### 验证
- [ ] 目标读者能够快速说出主题与主要发现。
- [ ] 读者能够完成预设比较、查询或探索任务。
- [ ] 已根据测试结果进行修订。
- [ ] 重要数据、计算和视觉映射经过复核。
