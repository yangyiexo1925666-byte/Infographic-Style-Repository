# 案例录入与知识回写规范 V3

## 1. 分类顺序与唯一主归属

1. 先根据作品的主导数据/信息关系，在 01 的五类中选择**唯一主归属**：编年型、层级型、编目型、字母表型、地理图型。
2. 可记录其他基础逻辑为辅助逻辑，但不得将两个逻辑并列写成“主要”。
3. 再从 02 的表现标签中选择一个主要标签，必要时增加辅助标签。表现标签不新增基础类型。
4. 最后记录统计图形、视觉编码及跨项目方法关联（ISOTYPE、Gestalt 等）。不能因使用普通图标就认定为 ISOTYPE。

## 2. 一图一档

每个 CASE 独立目录，至少包含：
- `分析.md`：五维分析与证据标记。
- `原图来源.md`：作者、机构、标题、链接、版本、访问日期、版权/许可状态；获准公开时可另存原图。
- `基础数据集.csv`：可复核的数据记录；无法转录时保留字段结构并注明缺失原因。
- `数据字典.md`：记录粒度、字段类型、单位、主键、来源、限制和缺失值含义。

## 3. 数据规范

- 一行一个最小观测单元；一列一个原子字段；一个单元格一个值。
- 记录稳定 ID、字段类型、单位、统计口径、时间范围和来源。
- 原始转录、清洗值、计算值和缺失值必须区分；不得从模糊图形反算精确数值。
- 未知、未采集、不适用和真实 0 不得混为一谈。
- 多对多关系拆成关联表；不将多个值塞入同一单元格。
- 无法可靠提取数值时，CSV 可先建立字段表/空数据结构，但必须标记“待核实”，不能把空表描述为完整数据集。

## 4. 五维分析与证据

A 数据逻辑；B 统计图形与计算；C 视觉编码；D 数据/信息架构；E 视觉叙事。每个关键判断标注【可观察】【来源明确】【分析推断】或【待核实】。作者实际制作过程与研究者可复用的重建流程必须分开。

## 5. 理论回写

案例分析完成后：
1. 更新所属表现标签的案例索引。
2. 更新全库案例索引。
3. 将可复核的基础逻辑观察链接回 01；理论文档不复制原图。
4. 将统计图形方法链接到 04；将有证据的方法关联链接到 ISOTYPE/Gestalt。
5. 单一案例只能形成观察，不直接升级为普遍规律；多个案例相互印证或反例出现后再修订理论。

## 6. 版权与来源

第三方作品未经明确授权，不上传原图；只保留官方来源链接和权利说明。外链不等于本地存档。图片来源、作者、发布日期不明确时必须如实标注待核实。

## 7. 案例状态
- 待分类：基础主归属无法判断。
- 待补来源：图面可分析但来源信息不完整。
- 待补数据：数据结构明确但原始数值无法可靠恢复。
- 已完成分析：五维分析完成，不代表来源、数据和版权均已核验。
- 已核验：来源、数据口径、权利状态及分析路径均有可复核证据。
