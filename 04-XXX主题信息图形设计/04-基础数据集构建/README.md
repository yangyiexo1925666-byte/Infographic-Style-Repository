# 04 基础数据集构建

## 核心原则：原子化字段（Atomic Data）

基础数据集要求字段结构清晰、可独立分析：

1. **一列只表达一个字段/一种变量。** 例如 `地点名称`、`纬度`、`经度`、`GDP` 分列保存。
2. **一个单元格只保存一个值。** 不在一个单元格中写“北京、上海、广州”；不把多个标签用逗号拼在一起。
3. **每列语义、数据类型、单位和口径一致。** 不把年份和日期混成一个字段，不把人民币和美元混用而不标记。
4. **名义、顺序、区间、比率等量化变量，以及文本、图像引用都可作为字段**，但应明确类型和编码规则。
5. **图像数据不直接塞进表格单元格。** 表格保存稳定的文件路径、URL 或 asset_id，图片文件独立归档。
6. **复杂关系拆表。** 多对多标签、多个地点、多张图片应建立关联表，而不是在一个格子里塞多个值。
7. **保留原始值。** 清洗和标准化结果另建字段或数据表，不覆盖原始记录。

## 推荐表结构

- `raw/`：原始数据，只读保存。
- `cleaned/`：清洗、统一单位、处理缺失后的数据。
- `analysis/`：计算、聚合、统计后的分析数据。
- `design-ready/`：为视觉编码整理的数据视图。
- `data-dictionary.md`：字段字典。
- `data-quality-report.md`：质量检查与处理日志。

## 主键与关系

每条记录应有稳定唯一的 `record_id`。地点、人物、事件等实体可使用独立 ID 和关联表连接。不要把复合信息拼成不可拆解的字符串作为唯一数据来源。

## 缺失值与特殊值

区分：未知、未采集、不适用、拒绝回答、确认为 0。不得把空白、0 和未知混为一谈。
